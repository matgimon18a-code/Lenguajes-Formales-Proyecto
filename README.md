## Project Description

This project implements an interpreter for a rule-based language. The system reads a set of rules of the form `if <condition> then <action>` along with an initial state, and evaluates which facts get activated using a fixed-point execution model.

The system includes:
- Lexical analysis (Lexer)
- Syntactic analysis with AST construction (Parser)
- Interpreter / Evaluator
- Basic static analysis (conflicts, redundancies, potentially inactive rules)

## Project Structure

```
lenguaje_reglas.py    # Main file, contains all modules
README.md             # This file
```

All the code lives in a single file `lenguaje_reglas.py`, organized in clearly separated sections:

### 1. Lexer (Lexical Analyzer)
Located at the top of the file. The `lexer(texto)` function takes the full program as a string and returns a list of tokens. Each token is a tuple `(type, value)`, for example:
- `('rule', 'rule')` — keyword
- `('ID', 'temp')` — identifier
- `('NUM', 35)` — integer literal
- `('>', '>')` — comparison operator

Recognized token types: `rule`, `if`, `then`, `AND`, `>`, `<`, `=`, `:`, `ID`, `NUM`, `EOF`.

### 2. Parser (Syntactic Analyzer)
The `Parser` class implements a **recursive descent parser** following the project's grammar:

```
Program  → RuleList
RuleList → Rule RuleList | ε
Rule     → rule id : if Cond then Action
Cond     → Atom (AND Atom)*
Atom     → id RelOp value | id
RelOp    → > | < | =
Action   → id
```

The `AND` operator is handled iteratively to avoid left recursion. The parser builds an **Abstract Syntax Tree (AST)** using Python dictionaries. Node types:

| Node type | Fields                          |
|-----------|---------------------------------|
| `Rule`    | `nombre`, `condicion`, `accion` |
| `And`     | `izq`, `der`                    |
| `Cmp`     | `id`, `op`, `valor`             |
| `Fact`    | `id`                            |

### 3. Interpreter (Evaluator)
- `evaluar_condicion(condicion, variables, hechos)` — recursively evaluates a condition node, returning `True` or `False`.
- `ejecutar_programa(reglas, variables, hechos_iniciales)` — runs the fixed-point loop: repeatedly applies all applicable rules until no new facts are added.

### 4. Static Analysis
`analisis_estatico(reglas, hechos_activados)` checks for:
- **Conflicts:** same action generated by rules with different conditions → `Action <id> generated by r1, r2`
- **Redundancies:** rules with identical condition and action → `Redundant rules: r1, r2`
- **Potentially inactive rules:** rules whose action was never activated → `Potentially inactive rule: <id>`

### 5. Initial State Parser
`parsear_estado(texto_estado)` reads the initial state block. Each line is either:
- `id = integer` → variable assignment
- `id` → active fact

### 6. Main Orchestrator
`correr_programa(texto_completo)` ties everything together: splits rules from state, runs the full pipeline, and prints the output.

## Input Format

A program consists of two parts separated by `State:`:

```
rule r1:
if temp > 30 then alert

rule r2:
if alert then fan_on

State:
temp = 35
```

**Rules** follow the grammar exactly. Each rule must have the `rule id:` header and the `if ... then ...` body.

**State** contains variable assignments (`id = integer`) and/or active facts (`id`), one per line.

---

## Output Format

- Each activated fact printed on a separate line, in **alphabetical order**.
- If no facts are activated: `(no output)`
- Static analysis messages are printed after the output, under `Analysis:` (only if there are messages).

## How to Run

### Option A — Visual Studio Code (or any terminal)

**Requirements:** Python 3.8+ installed. No additional packages needed.

**Steps:**

1. Open a terminal in the folder where `lenguaje_reglas.py` is located.
2. Run:
   ```bash
   python lenguaje_reglas.py
   ```
3. You will see this menu:
   ```
   Selecciona modo:
     1 - Correr todos los casos de prueba
     2 - Ingresar programa manualmente
   Opcion:
   ```
4. **Option 1** runs all 9 built-in test cases automatically.
5. **Option 2** lets you type a program manually. Enter your rules and state, then type `FIN` on a line by itself to run it:
   ```
   rule r1:
   if temp > 30 then alert
   State:
   temp = 35
   FIN
   ```

---

### Option B — Google Colab

**Steps:**

1. Open [Google Colab](https://colab.research.google.com) and create a new notebook.

2. In the first cell, paste the entire contents of `lenguaje_reglas.py`.

3. **To run the built-in test cases**, add this at the very end of the cell (after all the code):
   ```python
   correr_casos_prueba()
   ```
   Then run the cell (`Shift + Enter`).

4. **To run a custom program**, add this at the end instead:
   ```python
   correr_programa("""
   rule r1:
   if temp > 30 then alert
   State:
   temp = 35
   """)
   ```

   > **Note:** In Colab, `input()` works but can behave differently. It is recommended to use `correr_programa(...)` directly with your program as a string, rather than the interactive mode (option 2).

## Language Constraints

- Identifiers: lowercase letters, digits, and underscores. Must start with a letter.
- Integers: base-10, non-negative.
- Keywords (`rule`, `if`, `then`, `AND`) are case-sensitive.
- The only logical connective is `AND`. No `OR`, `NOT`, or parentheses.
- Extra whitespace and blank lines are ignored.
